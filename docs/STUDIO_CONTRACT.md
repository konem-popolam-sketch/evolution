Никаких `git commit`, никаких правок вне `studio/`.

## Зачем

50 субъагентов пользователя (плагин `@dsgs/dsh-agent-roster`) должны:
1. иметь **сохраняемую роль** (первым 12 — базовая из `roster.json`, остальным пусто до первого назначения);
2. помнить, **что уже делали** (память, чтобы не начинать с нуля);
3. показывать в комнатах студии **кто работает и что делал** (клик по персонажу → панель);
4. называться в интерфейсе «субъагент», а не «агент».

## Где данные (рантайм, пишет host-половина плагина)

`~/.dsh/agents/` (переопределяется `DSGS_AGENTS_DIR`):

- `roles.json` — `{ "variant": "1", "slots": { "<slot>": { "role": "текст роли", "assignedAt": "ISO", "source": "base"|"assigned" } } }`
- `memory/<slot>.md` — markdown: `# Имя · слот`, `## Роль`, `## Стиль работы`, `## Сделано` (append-only строки `- YYYY-MM-DD · <что сделал>`), `## Заметки`.
- `activity.jsonl` — по строке на событие, `{ts, slot, team, taskId, subject, status, summary}`.

Базовые роли: первые 12 слотов в порядке `TIER_ORDER` (exec → director → lead) из `roster.json`,
роль = поле `fn` (например `producer` → «спринты, вехи, скоуп»). Остальные 38 — роль `""`.

## API host-половины (`studio/roster/index.js`)

- `GET /plugins/dsgs-agent-roster/state` — как сейчас (`{style, agents:{slot:{state,since,until,team}}}`)
  **плюс** `roles: {slot: {role, source}}` и `recent: {slot: [ {taskId, subject, status, summary, at} ]}`
  (последние 10 по слоту, новые первыми; `summary` ≤ 180 символов).
  История берётся из всех `.agent-teams/*/team.json` (задачи с `assignee`, маппинг имя→слот тем же
  `slotForMember`), плюс строки `activity.jsonl`.
- `POST /plugins/dsgs-agent-roster/role` `{slot, role}` → сохраняет, `{ok:true, roles}`.
- `GET /plugins/dsgs-agent-roster/memory/<slot>` → `text/markdown`; `POST` с телом `{entry}` → дописывает
  строку в `## Сделано`, отвечает `{ok:true}`.
- Всё остальное — 404; слот валидируется `/^[a-z0-9-]+$/`, роль ≤ 200 символов.

## Клиент (`studio/roster/client.js`)

- Клик по персонажу открывает карточку субъагента: имя, слот, роль, статус, последние 10 дел
  (subject + summary + время). Закрытие — Esc/клик мимо/повторный клик.
- Данные только из `/state` (поллинг уже есть), без новых сетевых зависимостей.
- Тексты интерфейса: «субъагент/субъагенты», никаких «агент» в видимых подписях.
- Не ломать существующую анимацию комнат, состояния working/waiting/resting и фолбэк-панель.

## Студия 3.0 — стена субъагентов в панели Agent Teams

Вторая половина интерфейса, которую видит пользователь: страница «Studio» в панели
Agent Teams (`@nanmicoder/dsh-agent-teams`, локальный UI-патч внутри
`lib/client.js`). Она уже поллит `/plugins/dsgs-agent-roster/state`, но использует
только `agents` (статусы) и берёт подписи из зашитой таблицы `WALL_AGENTS`
(имя + функция). Поэтому роли и дела не видны.

Рабочая копия: `studio/agent-teams/lib/client.js` (312 344 Б) — править только её.
Установка — капитаном: копия в `<profile>/node_modules/@nanmicoder/dsh-agent-teams/lib/client.js`
с бэкапом `*.bak-studio-<дата>`; после установки нужен полный перезапуск DSH.

Требования:

1. `useWallPolling` должен пробрасывать `roles` и `recent` из `/state` (ключи те же, что в контракте ростера).
2. Карточка стены (`wallCard`) показывает: имя, **роль из `roles[slot].role`** (или «роль не назначена»),
   **последнее дело** из `recent[slot][0]` — subject (до ~40 символов) + относительное время
   («5 мин назад»), и текущий индикатор статуса. Функцию из `WALL_AGENTS` показывать только если роли нет.
3. Клик по карточке — поповер/диалог с до 10 делами (subject, summary, время), закрытие Esc/клик мимо.
4. Тексты (en-словарь и хардкод в разметке) — про субъагентов, по-русски:
   `plate.studioTitle` «Студия субъагентов», `plate.zone`/`plate.boardHint` «Стена субъагентов»,
   `plate.agents` «Субъагенты», `plate.bossLine` «Босс + 49 субъагентов», `plate.live` «на работе»,
   `plate.resting` «отдыхают», `plate.tabStudio` «Студия», `plate.tabTeam` «Команда»,
   `plate.boss` «Босс», `plate.openZone` «Открыть зону команды». Слово «agent» в видимых строках не оставлять.
5. Ничего не менять в логике планировщика, задач, почты капитана и панели активности.
6. `node --check studio/agent-teams/lib/client.js` должен проходить; список существующих
   функций/регистраций до и после — без потерь.
